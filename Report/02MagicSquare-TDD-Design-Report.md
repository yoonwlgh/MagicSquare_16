## Executive Summary

이번 문서의 1차 목표는 **4×4 정수 격자의 유효성 판정 규칙을 테스트 가능한 계약으로 고정**하는 것이다.  
유효 격자 산출은 2차 목표이며, 1차 계약의 완료 조건에 포함하지 않는다.

### 이번 문서가 해결하는 것

- 불변식 I-1~I-10을 테스트 가능한 설계 항목으로 분해
- 판정 계약(입력/출력/오류 관찰 가능 정보)의 1차 고정
- 최소 시나리오와 P0 우선순위 기반 TDD 착수 조건 정의

### 이번 문서가 하지 않는 것

- 코드, 테스트 구현, 알고리즘, 언어·프레임워크 선정
- UI/CLI 설계, n×n 일반화, 모든 해 나열

## 전제 및 문제 정의 정렬

본 설계는 `01MagicSquare-Problem-Definition-Report.md`의 정확한 정의를 그대로 따른다.

> 4×4 정수 격자의 제약 만족 여부를 판정 가능하고 반복 가능한 규칙으로 고정하며, 테스트로 회귀 가능하게 만든다.

### 표면 정의 vs 정확한 정의 정렬

| 구분 | 채택 여부 | 이유 |
|------|-----------|------|
| 34가 되는 격자 한 장을 만든다 | 미채택 | 대리 지표이며 회귀 기준을 제공하지 못함 |
| 제약 만족 판정 규칙을 고정·검증한다 | 채택 | TDD의 대상이 명확하고 반복 검증이 가능함 |

### I-1~I-10 / T-1~T-7 추적 표

| 원본 항목 | 본 설계 반영 방식 |
|-----------|-------------------|
| I-1~I-3 | 입력 형태/범위/중복 검사 레이어로 분리 |
| I-4~I-7 | 행·열·대각 합 검사 레이어로 분리 |
| I-8 | 전체 유효성 조합 규칙(AND 결합)으로 고정 |
| I-9 | 동일 입력 재판정 시 동일 결과 시나리오 포함 |
| I-10 | 계약 변경 시 테스트 수정 의무를 프로세스 규칙화 |
| T-1 | 판정 책임과 생성 책임 분리 |
| T-2 | 다중 제약 교집합 기반 시나리오 구성 |
| T-3 | 불변식 단위 테스트 관심사 매핑 |
| T-4 | 입력 경계와 출력 형태를 계약으로 명시 |
| T-5 | P0 회귀 스위트 우선 운영 |

| T-7 | 실패 유형을 위반 카테고리로 구조화 |

## In Scope / Out of Scope (TDD 설계 단계)

### In Scope

- 4×4 정수 격자 유효성 판정 계약
- 불변식 I-1~I-10 매핑과 검사 순서
- 테스트 전략(Red-Green-Refactor 적용 방식)
- 최소 시나리오 정의(P0/P1)
- 실패 유형 분류 및 회귀 원칙

### Out of Scope

| 항목 | 제외 근거 |
|------|-----------|
| 구현 언어·프레임워크 | 설계 단계의 계약 안정화가 선행되어야 함 |
| 생성 알고리즘 | 2차 목표이며 1차 판정과 책임 분리 필요 |
| UI/CLI | 판정 규칙의 본질과 독립 |
| n×n 일반화 | 4×4 고정 계약의 안정화 이전 확장은 리스크 |
| 모든 해 나열 | 요구 범위 외, 테스트 비용 과대 |

## 1차 계약 결정 (열린 질문 해소)

### 결정 요약

| ID | 결정 주제 | 선택 | 선택 이유 | Trade-off |
|----|-----------|------|-----------|-----------|
| D-1 | 1차 계약 범위 | 유효성 판정만 포함 | 핵심 목표와 정합, 회귀 단순화 | 생성 기능 요구가 들어오면 별도 계약 필요 |
| D-2 | 판정 결과 형태 | bool + 위반 카테고리 목록 | 실패를 정보로 활용(T-7), 디버깅/테스트 명확 | 결과 구조가 bool 단독보다 복잡 |
| D-3 | 입력 표현 | 기본 4×4 정수 2D 배열, 형태 위반 입력은 거부 | I-1과 직접 정합, 도메인 표현 명확 | 1D 입력 사용 시 사전 변환 필요 |
| D-4 | 검사 순서·단락 | 형태/범위/중복 선검사 후 합 검사, 치명 위반 시 합 검사는 생략 | 오류 원인 분리, 계산 낭비 감소 | 단일 실행에서 다중 위반 동시 수집은 제한됨 |
| D-5 | 마법 상수 | 4×4에서는 M=34 고정 | 현재 범위와 완전 일치 | 일반화 시 계약 재정의 필요 |

### 계약 문장(테스트 고정용)

- D-1: "1차 릴리스는 4×4 격자의 유효성 판정만 책임지며, 유효 격자 생성은 포함하지 않는다."
- D-2: "판정 결과는 `isValid`와 `violations`를 동시에 제공해야 하며, `isValid=true`일 때 `violations`는 비어 있어야 한다."
- D-3: "입력은 4×4 정수 배열만 허용하며, 형태/타입 위반 입력은 유효성 판정 이전에 거부한다."
- D-4: "형태·범위·중복 위반이 있는 경우 합 검사(I-4~I-7)를 수행하지 않고 해당 위반을 우선 보고한다."
- D-5: "4×4 판정 규칙에서 마법 상수는 34로 고정한다."

|------|------|

| Violation | 위반 카테고리(형태/범위/중복/행/열/대각/결정론 등) |

### 책임 분리(개념도)

```text
[입력 Grid]
   |
   v
[Validation Domain]
  |- 구조/집합 검사 (I-1~I-3)
  |- 합 검사 (I-4~I-7)
  |- 결합 판정 (I-8)
  |- 결정론/계약 고정 (I-9~I-10)
   |
   v
[ValidationResult]

[Generation Domain]  <-- 2차 목표 (본 설계 범위 밖)
```

## 불변식 → 테스트 관심사 매핑

| Invariant | 검사 내용 | 대표 무효 패턴 | 테스트 레벨 제안 |
|-----------|-----------|----------------|-------------------|
| I-1 | 4행 4열 형태 | 3×4, 4×3, 4행이지만 열 수 불일치 | 단위/계약 |
| I-2 | 값 범위 1~16 | 0, 17, 음수 포함 | 단위 |
| I-3 | 16개 고유성 | 중복 값, 누락 값 | 단위 |
| I-4 | 행 합=34 | 특정 행만 34 아님 | 단위/통합 |
| I-5 | 열 합=34 | 특정 열만 34 아님 | 단위/통합 |
| I-6 | 주대각 합=34 | 주대각만 불일치 | 단위 |
| I-7 | 부대각 합=34 | 부대각만 불일치 | 단위 |
| I-8 | 전체 결합 | 일부 위반인데 유효로 판정되는 경우 | 통합/계약 |
| I-9 | 동일 입력 동일 결과 | 동일 입력 두 번 결과 불일치 | 계약 |
| I-10 | 규칙 변경 관리 | 계약 변경 없이 테스트만 우회 | 프로세스/계약 |

### I-8, I-9, I-10 회귀 원칙

- I-8: "전체 유효성은 부분 규칙의 AND 결합"을 회귀 스위트의 최상위 규칙으로 유지한다.
- I-9: 동일 픽스처 재실행 결과가 완전히 일치해야 한다(유효 여부 + 위반 목록).
- I-10: 규칙 변경 시 테스트 케이스/문서 계약을 동시 갱신하지 않으면 변경을 거부한다.

## 테스트 전략 (TDD)

### Red → Green → Refactor 적용

- Red: 불변식별 실패 시나리오를 먼저 작성해 현재 계약 부재를 드러낸다.
- Green: 최소 규칙으로 해당 시나리오를 통과시킨다(과잉 일반화 금지).
- Refactor: 중복 검사 로직을 정리하되 계약(시나리오 기대값)은 고정한다.

### 테스트 레이어

| 레이어 | 목적 | 예시 범위 |
|--------|------|-----------|
| L1 규칙 단위 | I-1~I-7 개별 규칙 검증 | 형태/범위/중복/행·열·대각 |
| L2 조합 판정 | I-8 결합 검증 | 부분 실패 시 전체 실패 |
| L3 계약/회귀 | I-9~I-10 검증 | 동일 입력 동일 결과, 계약 변경 관리 |

### 테스트 이름 규칙

- 형식: `should_<기대결과>_when_<조건>`
- 예: `should_return_invalid_when_duplicate_numbers_exist`

### 픽스처·골든 격자 원칙

- 유효 골든 격자 최소 1개 유지
- 무효 유형별 최소 1개 픽스처 유지
- 픽스처 목적(어떤 불변식 위반 검증용인지)을 메타데이터로 명시

### 완료 기준(대리 지표 거부)

- "유효 격자 하나 통과"는 완료가 아니다.
- P0 무효 유형이 모두 계약대로 실패해야 1차 TDD 완료로 본다.

### P0만으로 1차 TDD 착수 가능성

**Yes.**  
P0는 유효 기준(S-001), 핵심 무효 유형(S-002~S-009), 결정론(S-010)을 모두 포함한다.  
따라서 판정 계약의 최소 완결 조건(I-1~I-9)을 구현 전부터 충분히 고정할 수 있다.

## 2차 목표(선택): 유효 격자 하나 산출

2차 목표는 "유효 격자 생성"이며, 1차 판정 계약 완료 이후 별도 계약으로 정의한다.

### 2차에서 새로 필요해지는 계약(개요)

- 생성 결과의 유효성은 1차 판정 계약을 재사용해 검증한다.
- 생성 실패/시간 초과 정책은 별도 비기능 요구로 정의한다.
- 생성 전략(탐색/패턴 기반)은 본 문서 범위 밖에서 선택한다.

### 1차와 섞으면 안 되는 이유

- 판정과 생성은 실패 원인과 책임이 다르다.
- 동시 진행 시 TDD의 실패 신호가 흐려진다.
- 1차 회귀 스위트 안정화가 늦어져 계약 품질이 저하된다.
