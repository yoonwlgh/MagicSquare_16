## Executive Summary

### 한 줄 요약

4×4 마방진 과제의 진짜 목표는 **「34가 나오는 격자 한 장」**이 아니라, **「명시된 제약을 만족하는지 판정하는 규칙을 고정·반복·검증 가능하게 만드는 것」**이다.

### 핵심 발견

1. **표면 문제**는 퍼즐 완료(배치 산출)에 치우쳐 있고, 학습·증명 목적과 어긋난다.
2. **프로그램**은 계산 대신 **반복 가능한 절차·자동 검증·규칙의 명시적 분해**를 위해 필요하다.
3. **TDD**는 작아서가 아니라, **다중 불변 조건·모호한「완성」·검증/생성 책임 혼동**을 통제하기 위해 맞다.
4. **정확한 문제 정의**는 판정 규칙과 불변식(I-1~I-10)을 중심으로 하고, 격자 산출은 2차 목표로 둔다.

### STEP별 결론

| STEP | 질문 | 결론 |
|------|------|------|
| 1 | 무엇을 다루는 상황인가? | 4×4 격자에서 행·열·대각 합 동일 + 1~16 각 1회 제약;「만든다」보다 규칙·검증 관점 |
| 2 | 왜 완성해야 하는가? | (가정) 제출·증명 — 대리 지표·완성 기준 모호·방법론 공백 등 구조적 긴장 |
| 3 | 왜 프로그램인가? | 반복·검증 자동화·오류 방지·규칙 기반 사고 — 손계산 한 번과 목적이 다름 |
| 4 | 왜 TDD인가? | 통제 대상은 판정 절차; 불변식 층분리; 입출력 계약으로 책임 분리 |
| 5 | 진짜 문제는? | 유효성 **판정** 규칙의 고정·회귀; 핵심 Invariant 10항; 사고 능력 T-1~T-7 |

### 핵심 Invariant (요약)

- **구조·집합:** 4×4, 값 1~16, 중복 없음
- **합:** 각 행·열·주대각·부대각 합 = 34
- **판정:** 전부 만족 시에만 유효; 동일 입력 → 동일 결과; 규칙 변경은 계약 변경

### 훈련 목표 사고 능력 (요약)

명세 분리, 다중 제약 교집합, 불변식 식별, 입출력 계약, 검증 우선·회귀, 대리 지표 거부, 실패를 정보로 활용.

### 의도적 제외 (본 보고서)

- 구현 설계
- 코드·언어·프레임워크
- 알고리즘·생성 방법

## STEP 1 — Observation (관찰)

**단계:** STEP 1 — 문제 인식 (관찰)  
**제약:** 설계·구현 없음

### 1. 현재 우리가 해결하려는 상황은 무엇인가?

**4×4 격자에 1부터 16까지의 정수를 한 번씩 배치했을 때, 행·열·대각선 합이 모두 동일한지 확인·생성하는 규칙을 다루는 상황**이다.

#### 관찰 관점 서술

| 관찰 항목 | 내용 |
|-----------|------|
| **입력·출력** | 4×4 배열(또는 16개의 수)이 주어지거나, 「유효한 배치」를 찾아야 함 |
| **제약** | 16개의 서로 다른 정수(보통 1~16), 각 행·각 열·두 대각선의 합이 같음 (마법 상수 **34**) |
| **불확실성** | 「만든다」가 검증만인지, 하나 찾기인지, 모두 나열인지, 사용자 입력인지 아직 정의되지 않음 |
| **프로젝트 맥락** | 저장소 MagicSquare_JH — 학습·과제·개인 프로젝트로 처음부터 문제를 정의하려는 **초기 단계** |

#### 표현 전환

- ❌ 「마방진 앱을 만든다」
- ✅ **「4×4 정수 격자에서 행·열·대각선 합 동일 조건을 만족하는 배치를 어떻게 다룰 것인가」**

### 2. 왜 4×4 마방진 문제를 다루는가?

확정 답은 추가 정보 필요. 관찰 가능한 동기 후보:

| 관점 | 관찰 |
|------|------|
| **규모** | 3×3보다 제약이 많고, 5×5보다 계산이 가벼워 알고리즘·자료구조 연습에 적합 |
| **수학** | 합=34, 대칭·패턴이 있어 규칙 탐색·증명과 연결 |
| **구현** | 2차원 배열, 반복, 합 계산, 탐색 등 프로그래밍 기본기를 한 주제에 모을 수 있음 |
| **명명** | 프로젝트명이 Magic Square를 가리켜 주제가 4×4로 고정된 것으로 보임 |

**가능한 이유:** 과제 명세, 강의 예제, 「작지만 비자명한」난이도, 이후 n×n 확장의 첫 단계.

### 3. 어떤 학습 또는 시스템 설계 맥락에서 등장하는가?

#### 학습 맥락

- 입문 알고리즘 (탐색 vs 규칙 기반, 복잡도 직관)
- 이산수학·조합 (제약 만족, 해의 공간)
- 자료구조 (2D 배열, 불변 조건 검사)
- 테스트·검증 (마법 상수 34, 중복·범위 오류)

#### 시스템 설계 맥락 (확장 시)

- **검증 서비스:** 외부 격자의 규칙 만족 판정
- **생성/힌트:** 퍼즐·교육 도구의 한 모듈
- **UI 분리:** 규칙 엔진 vs 표시·입력

#### 아직 구분되지 않는 것

단일 CLI 프로그램인지, 라이브러리+UI인지, 과제 제출용인지 — 관찰만으로는 불명.

### STEP 1 요약

| 피해야 할 표현 | 관찰 관점 표현 |
|----------------|----------------|
| 마방진을 만든다 | 4×4 격자에 1~16을 배치해 행·열·대각선 합이 같은지 검사하거나, 그런 배치를 찾는다 |
| Magic Square 프로그램 | 16칸 배열과 합-34 불변 조건을 다루는 소프트웨어 과제 |
| 구현한다 | 문제 범위·성공 기준을 정하는 단계 |

## STEP 2 — Why #1

**질문:** 왜 마방진을 완성해야 하는가?  
**방법:** 답(A)을 가정한 뒤, 불편함·구조적 문제 분석

### 가정한 답 (A)

> **4×4 마방진을 완성해야 하는 이유는, 주어진 수학적 규칙(행·열·대각선 합 동일, 1~16 각 한 번)을 프로그램으로 만족시키는 결과를 만들어, 과제·학습·포트폴리오에서 「요구된 산출물」을 제출·증명하기 위해서이다.**

**핵심:** 목적은 「마방진 그 자체」가 아니라 **「규칙을 소프트웨어로 구현했다는 증거」**에 가깝다.

### 그 답에서 드러나는 불편함

#### 1. 「완성」의 기준이 모호함

- 완성 = 한 격자 출력 / 검증 통과 / 모든 해 / 사용자 퍼즐 — 구분 없음
- 「한 번 34 배치」와 「임의 입력 판정」은 노력이 전혀 다름
- **불편함:** 목표는 제출인데 성공 정의가 흔들리면 끝 시점을 알 수 없음

#### 2. 수단(마방진)과 목적(능력 증명)의 뒤바뀜

- 진짜 원하는 것: 제약 만족·탐색·검증·구조화
- 평가는 「34가 나오는 격자」에 고정되기 쉬움
- **불편함:** 고정 패턴 복사로 산출물만 통과, 이해는 비어 있을 수 있음 → **통과 ≠ 이해**

#### 3. 4×4 크기가 만드는 착시

- 완전 탐색·공식·대칭 변환 모두 가능 → 어렵고 쉬움이 공존
- **불편함:** 허용 방법(암기·탐색·수학) 미정 시 공정성·성취감 흔들림

#### 4. 외부 게이트(제출·채점) 중심의 시간 구조

- 마감·채점 → 「일단 돌아가는 출력」 우선
- **불편함:** 경계·예외·검증이 뒤로 밀리고, 한 번 성공한 실행이 완성으로 오해됨

#### 5. 「하나의 정답 격자」 vs 「해의 공간」

- 해가 여러 개, 회전·대칭 동치 다수
- Why가 「완성(하나)」이면 하나만 내면 성공
- **불편함:** 첫 해 찾기 vs 해 개수·분류는 문제 규모가 다름; 「유일한 완성」인지 구분 안 됨

#### 6. 학습 목표와 시스템 책임의 불일치

| 역할 | 책임 |
|------|------|
| 생성자 | 맞는 것을 만들어 준다 |
| 판정자 | 왜 틀렸는지 말해 준다 |
| 탐험자 | 가능한 배치를 보여 준다 |

Why #1만으로는 셋이 한 목표로 압축됨.

### 구조적 문제 요약

| 구조 | 내용 |
|------|------|
| **대리 지표** | 마방진 완성 = 능력 증명의 대리물; 대리물만 맞추면 형식상 목적 달성 |
| **성공 정의 부재** | 완성·검증·생성·나열이 한 단어로 뭉개짐 |
| **방법론 공백** | 허용 해법 미정 → 공정성·학습 깊이 모호 |
| **크기 착시** | 4×4는 역할에 따라 난이도 급변 |
| **단일 산출물 편향** | 한 격자만이면 해 공간·오류 설명은 설계 밖 |

### STEP 2에서 열린 질문

1. **완성**의 최소 정의는? (한 격자 / 임의 입력 검증 / 교육용 피드백)
2. **허용되는 방법**은? (표준 배치 암기 vs 탐색)
3. **누가** 「완성했다」고 판단하는가?

## STEP 3 — Why #2

**질문:** 왜 단순 계산이 아니라 프로그램으로 구현하는가?

### 전제

4×4에서 16개 수 배치와 10개 선(행 4 + 열 4 + 대각 2)의 합 맞추기는 **한 번**이면 종이·계산기로 가능하다. 프로그램의 이유는 「34를 한 번 구함」이 아니라 **과정을 재현·검사·일반화**하는 것이다.

### 1. 반복 가능성 (Repeatability)

| 손계산 | 프로그램 |
|--------|----------|
| N번 검사 시 피로·주의력 저하 | 동일 절차를 N번 실행해도 절차 동일 |
| 다른 입력·부분 격자 = 매번 새 작업 | 입력만 바꿔 같은 규칙 반복 적용 |
| 해 하나 암기 후 변형은 다시 손으로 | 실험 루프(시도·탐색) 가능 |

**의미:** 「이 규칙을 만족하는가?」를 여러 경우에 동일 적용하려면 **외부화된 반복 단위**가 필요.

**구조적 문제:** 「한 번 출력」만 있으면 Why #2를 충분히 만족하지 못함.

### 2. 검증 자동화 (Automated Verification)

검증은 단순 합산이 아님:

- 1~16 각 1회인지 (중복·누락·범위)
- 10개 선의 합이 모두 34인지
- (목표에 따라) 부분 격자·중간 상태

**손계산:** 행만 보고 끝, 합은 34인데 7이 두 번 등 **누락 검사** 위험.

**프로그램:** 규칙을 명시적 조건으로 기계적 판정; 테스트 케이스 저장·회귀.

**의미:** 「맞는 배치 찾기」≠ 「주어진 배치 자동 증명·반증」.

### 3. 오류 방지 (Error Prevention)

| 오류 유형 | 손계산 | 프로그램 관점 |
|-----------|--------|----------------|
| 덧셈 실수 | 흔함 | 합 로직 맞으면 재현 시 감소 |
| 검사 누락 | 행만 확인 등 | 검사 목록을 절차에 넣으면 감소 |
| 규칙 혼동 | 합만 같으면 됨 vs 1~16 각 1회 | 조건 분리 안 하면 버그로 고정 |
| 재현 불가 | 어제 맞고 오늘 틀림 | 입력·버전 추적 가능 |

**구조적 문제:** 「일단 출력」만 하면 오류는 다시 **눈으로 검사**로 회귀.

### 4. 규칙 기반 사고 훈련 (Rule-Based Thinking)

마방진 = 하나의 숫자(34)가 아니라 **여러 규칙의 교집합**.

- 전역: 행·열·대각 합 = 34
- 집합: {1,…,16} 순열
- (생성 시) 추가 제약

**구조적 문제:** 표준 배치 통째 출력만 하면 훈련 거의 없음.

### Why #2 종합

> **단순 계산은 「한 번의 답」을 준다. 프로그램은 「규칙을 담은 절차」를 준다.**

4×4 맥락에서 프로그램을 쓰는 이유:

1. 같은 규칙을 여러 입력·시도에 **반복**
2. 맞음/틀림을 **자동 검증**
3. 검사 누락·규칙 혼동을 **절차로 줄임**
4. 여러 제약을 **분해·수정 가능**하게 **훈련**

**제출물의 진짜 가치:** 격자 한 장보다 **반복·자동 검증·명시적 규칙**.

### STEP 2와의 연결

| Why #2 | STEP 2 긴장 |
|--------|-------------|
| 반복 | 한 격자만 내면 반복 필요성 소멸 |
| 검증 자동화 | 생성만 하고 눈으로 검증하면 목적 상실 |
| 오류 방지 | 절차 버그는 재현성 높은 오류 |
| 규칙 기반 사고 | 암기 출력은 네 가지 거의 불만족 |

## STEP 4 — Why #3 (핵심 발견) — TDD 관점

**질문:** 왜 이 문제를 TDD 방식으로 설계하려 하는가?  
**제약:** 구현·코드·알고리즘 없음

### 한 줄 발견

4×4 마방진은 **겉보기엔 작은 산술**이지만 **여러 독립 규칙의 교집합**이다. TDD는 「34가 나온 격자」가 아니라 **어떤 규칙이 언제 성립해야 하는지**를 먼저 고정하는 설계 방식이다.

### 1. 무엇이 통제되어야 하는가?

| 통제 대상 | 왜 필요한가 | 흔들리면 |
|-----------|-------------|----------|
| **규칙의 범위** | 합만 vs 1~16 각 1회 | 잘못된 격자 통과 |
| **검사 순서·책임** | 행/열/대각/중복 한 덩어리 | 한 줄 수정이 전체 붕괴 |
| **성공·실패 의미** | bool vs 위반 종류 | 설명 불가 |
| **입력 형태** | 완성 vs 빈 칸 vs 잘못된 크기 | 오류가 도메인 버그처럼 보임 |
| **재현성** | 동일 입력 → 동일 판정 | 반복·검증 목적 상실 |
| **변경 지점** | 확장·범위 변경 | 한곳 수정이 전체 파괴 |

**핵심:** 통제 대상은 **「16개 숫자」가 아니라 「판정 절차와 명세」**.

### 2. 어떤 불변 조건이 존재하는가?

#### (A) 데이터·집합 불변

- 격자 4×4
- 값 1~16 범위
- 16개 값 서로 다름 (순열)

#### (B) 합(마법 상수) 불변 — M = 34

- 각 행·열·주대각·부대각선 합 = 34

#### (C) 논리적 불변 (판정기)

- 부분 검사 모두 통과 → 전역 「유효」
- 하나라도 위반 → 전역 「무효」
- 동일 입력 → 동일 판정

#### 층 구조

```text
집합 불변 (순열)  →  선형 불변 (행·열·대각 합)  →  전역 판정 (valid?)
```

**함정:** 합만 구현하고 순열 생략 → 규칙 혼동이 절차에 고정.

### 3. 왜 입력/출력이 명확해야 하는가?

#### 입력 모호 시

| 모호함 | 문제 |
|--------|------|
| 2D vs 1D 16개 vs 문자열 | 픽스처 형식 불일치 |
| 인덱스 기준 | 맞는데 틀림 |
| 빈 칸·미입력 | 부분 격자 vs 오류 불명 |
| 크기 혼합 | 4×4 불변식과 충돌 |

#### 출력 모호 시

| 모호함 | 문제 |
|--------|------|
| bool vs 위반 목록 | assert 불명 |
| 격자 출력 vs valid/invalid | 생성·검증 혼합 |
| 예외 vs false | 오류 방지 불일치 |

**책임 분리 (개념):**

- **판정기:** 격자 → 판정 결과
- **생성기:** (옵션) → 격자
- 둘 다면 **두 계약 분리**

### Why #3 종합

| 관점 | TDD의 역할 |
|------|------------|
| **통제** | 제출 목표를 판정 절차로 고정 |
| **불변 조건** | 순열·합·대각 층별 분리 |
| **입출력** | 검증 vs 생성 책임 분리; 「완성」을 계약으로 고정 |

> **발견:** 4×4는 「작아서 테스트 불필요」가 아니라 **「작아서 규칙이 많은데 한눈에 넘기기 쉽다」**.

### STEP 2·3과의 설계 압력

1. 테스트 먼저 → 암기 출력만으로는 부족, **판정 규칙** 선행
2. 불변식 테스트 → 반복·회귀 (Why #2)
3. 입출력 계약 → 오류 종류 분리 (Why #2)

### 열린 질문 (STEP 5에서 일부 해소)

- 1차 계약: **유효성 판정**만 vs **한 해 생성**까지?
- 실패: **bool** vs **위반 위치·종류**?

## STEP 5 — 진짜 문제 정의

**제약:** 구현 설계·코드·알고리즘 없음

### 1. 표면 문제 정의 (잘못된 정의)

> **「4×4 격자에 1부터 16까지 숫자를 넣어, 행·열·대각선 합이 모두 34가 되는 배치를 만든다.」**

#### 이 정의가 잘못된 이유

| 한계 | 설명 |
|------|------|
| **목표가 산출물 한 장** | 규칙 이해·재현·검증 여부가 드러나지 않음 |
| **책임 한 덩어리** | 만들기·확인·설명이 구분되지 않음 |
| **규칙 불완전** | 합만 같으면 된다고 읽힘; 각 수 1회 조건 누락 |
| **완료 시점 불명** | 다른 입력·회귀 필요 여부 미정 |
| **프로그램 정당화 약함** | 손계산·암기로도 표면 목표 달성 가능 |

### 2. 개선된 문제 정의 (정확한 정의)

> **「4×4 정수 격자에 대해, 명시된 제약(크기, 값의 범위·중복 없음, 지정된 모든 선에서의 합 동일)을 만족하는지 판정할 수 있는 규칙을 정의하고, 그 판정을 동일 입력에 대해 반복 가능하게 적용하며, 판정 기준을 외부에서 검사(테스트)할 수 있게 고정하는 것이다. 필요 시, 그 규칙을 만족하는 하나의 격자를 산출하는 것은 별도 목표로 둔다.」**

#### 정의 구성 요소

| 요소 | 내용 |
|------|------|
| **대상** | 4×4 정수 격자 (16칸) |
| **핵심 행위** | 제약 만족 **판정** |
| **제약** | 핵심 Invariant (아래) |
| **품질** | 동일 입력 → 동일 판정; 규칙은 테스트로 고정·회귀 |
| **선택 목표** | 유효 격자 하나 산출 — **2차** |
| **비목표(현 단계)** | 모든 해 나열, UI, n×n, 최적 생성 등 |

#### 성공 기준 (문제 관점)

- 알려진 **유효** 격자 → 「만족」
- 의도적 **무효** 격자 (합만 맞음, 중복, 범위, 크기 등) → 「불만족」
- 규칙 변경 시 기존 계약 깨짐 → 의도적 변경이 아니면 실패

### 3. 이 문제의 핵심 Invariant

#### 3.1 구조·집합 불변

| ID | 불변 조건 | 위반 시 |
|----|-----------|---------|
| **I-1** | 정확히 4행 4열 (16칸) | 판정 대상 비성립 |
| **I-2** | 각 값 ∈ [1, 16] | 범위 위반 |
| **I-3** | 16개 값 서로 다름 | 중복·누락 |

#### 3.2 선형(합) 불변 — M = 34

| ID | 불변 조건 | 위반 시 |
|----|-----------|---------|
| **I-4** | 각 **행** 합 = 34 | 행 위반 |
| **I-5** | 각 **열** 합 = 34 | 열 위반 |
| **I-6** | **주대각선** 합 = 34 | 주대각 위반 |
| **I-7** | **부대각선** 합 = 34 | 부대각 위반 |

#### 3.3 판정·운용 불변

| ID | 불변 조건 | 의미 |
|----|-----------|------|
| **I-8** | I-1~I-7 모두 참일 때만 「유효」 | 전역 = 부분 규칙의 결합 |
| **I-9** | 동일 격자 → 동일 판정 | 반복·자동 검증 전제 |
| **I-10** | 규칙 변경 = 계약(테스트) 변경 | 회귀와 우연 구분 |

#### 관계도

```text
I-1 (형태) → I-2, I-3 (집합) ─┐
                              ├→ I-8 (유효 판정)
I-4 ~ I-7 (합) ──────────────┘
         ↑
    I-9, I-10 (절차 일관성·고정성)
```

**주의:** I-4~I-7만 만족하고 I-3 무시 → 「합은 맞지만 마방진 아님」 통과 가능.

### 4. 우리가 실제로 훈련하려는 사고 능력

| # | 사고 능력 | 이 문제에서의 표현 |
|---|-----------|-------------------|
| **T-1** | **명세 분리** | 만들기 vs 판정하기 목표·성공 기준 분리 |
| **T-2** | **다중 제약 교집합** | 집합·행·열·대각이 동시에 성립해야 함 |
| **T-3** | **불변 조건 식별** | I-1~I-8 목록화·검사 단위 분할 |
| **T-4** | **계약·입출력** | 입력 경계·출력(만족/불만족·위반 종류) 명확화 |
| **T-5** | **검증 우선·회귀** | 한 번 맞춘 예보다 고정된 판정 기준 우선 |
| **T-6** | **대리 지표 거부** | 「격자 한 장」≠ 완료; 재검사 가능 규칙 = 완료 |
| **T-7** | **실패를 정보로** | 무효 유형 구분 → 명세 정교화 |

#### 훈련하지 않는 것

- 특정 배치 암기
- 손으로 한 번 34 맞추기
- 「작으니 눈으로 확인」

| 구분 | 표면 (잘못된) | 개선 (정확한) |
|------|----------------|----------------|
| **한 줄** | 34가 되는 격자를 만든다 | 제약 만족 **판정 규칙**을 고정·검증 |
| **성공** | 격자 한 장 | 반복 가능한 판정 + 계약 |
